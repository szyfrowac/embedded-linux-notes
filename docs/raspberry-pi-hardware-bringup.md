## 1. The Unique Raspberry Pi Boot Sequence

Unlike the BeagleBone Black (or most other ARM SoCs) where the ARM CPU wakes up first and runs a bootloader like U-Boot, the Raspberry Pi's Broadcom SoC (System on Chip) relies on its **VideoCore GPU** to orchestrate the boot sequence.

The ARM CPU is held in reset while the GPU initializes the system. 

![Raspberry Pi GPU Boot Sequence](/rpi_gpu_boot.png)

1. **Stage 1 (Boot ROM):** The GPU wakes up and executes immutable code baked into the SoC. It mounts the FAT32 partition on the SD card.
2. **Stage 2 (`bootcode.bin`):** The GPU loads this firmware file from the SD card. It enables the SDRAM (memory).
3. **Stage 3 (`start.elf`):** The GPU loads this core firmware. It reads `config.txt` (the Raspberry Pi equivalent of BIOS settings), configures the hardware (clocks, HDMI, GPIO), loads the Device Tree Blob (DTB), and finally loads the Linux Kernel (`kernel.img`) into RAM.
4. **Stage 4 (Linux Kernel):** The GPU releases the ARM CPU from reset, pointing it to the loaded kernel. Linux boots.

::: warning NO U-BOOT REQUIRED
By default, the Raspberry Pi skips U-Boot entirely! The GPU firmware (`start.elf`) directly loads the Linux Kernel. While it is possible to configure `start.elf` to load U-Boot instead (which then loads Linux), the standard Yocto `meta-raspberrypi` configuration follows the direct-boot approach.
:::

## 2. Building Yocto for the Raspberry Pi

The official BSP layer for all Raspberry Pi models is `meta-raspberrypi`. 

### Step 1: Clone the Layer

```bash
cd /path/to/poky
# Ensure the branch matches your Poky installation!
git clone -b kirkstone git://git.yoctoproject.org/meta-raspberrypi
```

### Step 2: Add to `bblayers.conf`

```bash
cd build/
bitbake-layers add-layer ../meta-raspberrypi
```

### Step 3: Configure `local.conf`

Edit your `conf/local.conf` to target the specific Pi model.

```bash
# For Raspberry Pi 3 (32-bit):
MACHINE = "raspberrypi3"

# For Raspberry Pi 3 (64-bit):
# MACHINE = "raspberrypi3-64"

# For Raspberry Pi 4 (64-bit):
# MACHINE = "raspberrypi4-64"

# Enable UART serial console (crucial for headless debugging!)
ENABLE_UART = "1"
```

### Step 4: Build the Image

```bash
bitbake core-image-minimal
```

## 3. Emulating Raspberry Pi with QEMU (No Hardware Required!)

If you don't have a physical Raspberry Pi, you can still boot your compiled Yocto image using QEMU. QEMU natively supports the `raspi3b` machine model.

```bash
# Navigate to the deploy directory
cd tmp/deploy/images/raspberrypi3

# Extract the rootfs if it's compressed
# (assuming IMAGE_FSTYPES includes ext3 or ext4)

# Run QEMU specifying the raspi3b machine, your kernel, DTB, and rootfs
qemu-system-aarch64 \
    -M raspi3b \
    -cpu cortex-a53 \
    -m 1G \
    -kernel zImage \
    -dtb bcm2710-rpi-3-b.dtb \
    -drive format=raw,file=core-image-minimal-raspberrypi3.ext3 \
    -append "rw earlyprintk loglevel=8 console=ttyAMA0,115200 dwc_otg.lpm_enable=0 root=/dev/mmcblk0 rootwait" \
    -no-reboot \
    -serial stdio \
    -nographic
```

## 4. Hardware Bring-Up (Physical Board)

If you have the physical hardware, use the `.wic` image generated by BitBake.

### 4.1 Flashing the SD Card

```bash
# WARNING: Identify the correct /dev/sdX for your SD card
sudo dd if=tmp/deploy/images/raspberrypi3/core-image-minimal-raspberrypi3.wic of=/dev/sdX bs=4M status=progress
sync
```

### 4.2 UART Serial Console Connection

Since `core-image-minimal` lacks SSH and video drivers, you must connect via the UART serial console.

**Wiring the FTDI USB-to-Serial Cable:**
1. Connect FTDI **GND** (Black) to Pi **Pin 6 (GND)**
2. Connect FTDI **TX** (Green) to Pi **Pin 10 (RXD)**
3. Connect FTDI **RX** (White) to Pi **Pin 8 (TXD)**
4. *Do NOT connect the VCC (Red) wire if the Pi is powered via USB-C/Micro-USB!*

**Connecting via Terminal:**
```bash
sudo picocom -b 115200 /dev/ttyUSB0
```
Power on the Raspberry Pi. You should see the kernel log followed by a login prompt. Login as `root` (no password).

## 5. Hands-On Lab Exercises

::: tip LAB 5.1: Analyzing the Boot Partition
Mount the flashed SD card (or inspect the `boot` directory in `tmp/deploy/images/raspberrypi3/`) on your host machine.
1. Locate `bootcode.bin` and `start.elf` (the closed-source Broadcom firmware).
2. Open `config.txt`. Notice how BitBake automatically populated `enable_uart=1` because you set `ENABLE_UART = "1"` in `local.conf`.
3. Locate the `kernel.img` (or `kernel7.img`/`kernel8.img` depending on architecture) and the `bcm27xx.dtb` Device Tree files.
:::
