## Measure with buildhistory

```bitbake
# conf/local.conf
INHERIT += "buildhistory"
BUILDHISTORY_COMMIT = "1"
```

Rebuild your image. Then look in `buildhistory/images/<machine>/<libc>/<image>/`:

```bash
cd buildhistory/images/*/*/core-image-minimal
sort -k2 -n -r installed-package-sizes.txt | head -15
```

`installed-package-sizes.txt` lists each package's installed size; `depends.dot` records why each package is there.

## Why is this package here?

```bash
grep '"python3-core"' depends.dot | head
```

Each line `"a" -> "b"` means `a` depends on `b`. Follow the chain back to something you added. Often a single convenience package in `IMAGE_INSTALL` pulls in an entire language runtime.

## Reductions, roughly in order of effort

1. **Remove what you do not need.** Check `IMAGE_INSTALL`, `IMAGE_FEATURES` and `DISTRO_FEATURES`. Dropping `x11`, `wayland`, `bluetooth` or `3g` from `DISTRO_FEATURES` removes support from many recipes at once.
2. **Turn off optional features per recipe** with `PACKAGECONFIG:remove:pn-<recipe>`.
3. **Stop installing recommendations**: `NO_RECOMMENDATIONS = "1"` in the image recipe skips every `RRECOMMENDS`. Check the image still works afterwards.
4. **Use smaller components**: BusyBox instead of coreutils and friends, Dropbear instead of OpenSSH, and `TCLIBC = "musl"` instead of glibc if your software builds with it.
5. **Compress the root filesystem**: `IMAGE_FSTYPES += "squashfs-xz"` for a read-only root.
6. **Trim the kernel**: start from a minimal defconfig for your SoC and add only what the board uses. Measure with `ls -l` on the kernel image in `tmp/deploy/images/<machine>/`.

:::note[poky-tiny]
`DISTRO = "poky-tiny"` is a reference distribution that applies many of these choices at once (musl, minimal features, a small kernel). It is a useful lower bound to compare against, even if your product cannot use it directly.
:::

## Track it

With `BUILDHISTORY_COMMIT = "1"`, every build is a git commit in `buildhistory/`. The `buildhistory-diff` script prints what changed in size and contents since the previous build, which makes size regressions visible in review rather than at release time.
