## Dropbear or OpenSSH

| | Dropbear | OpenSSH |
|---|---|---|
| Size on target | Around 100 to 200 KB | Several MB with its libraries |
| `scp` and `sftp` | `scp` needs the `scp` program present on the target | Full support |
| Yocto image feature | `ssh-server-dropbear` | `ssh-server-openssh` |
| Typical use | Small images, quick development access | Products that need sftp, port forwarding policies or certificates |

Pick one; the two image features conflict.

```bitbake
# conf/local.conf (development) or your image recipe
IMAGE_FEATURES += "ssh-server-dropbear"
```

In Buildroot, enable `BR2_PACKAGE_DROPBEAR` or `BR2_PACKAGE_OPENSSH` under *Target packages, Networking applications*.

## Log in with a key

Password logins are slow to type and easy to guess. Generate a key on the host once, then install the public half on the target:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/target_ed25519
ssh-copy-id -i ~/.ssh/target_ed25519.pub root@192.168.7.2
ssh -i ~/.ssh/target_ed25519 root@192.168.7.2
```

To bake the key into the image instead, install it from a recipe into `/home/root/.ssh/authorized_keys` with mode `0600`, owned by root.

:::danger[debug-tweaks]
`IMAGE_FEATURES += "debug-tweaks"` (renamed in newer Yocto releases to `allow-empty-password`, `empty-root-password` and `post-install-logging`) lets root log in with no password. It is convenient on the bench and must never reach a shipped image. Check your image recipe and `local.conf` before a release build.
:::

## The edit, build, copy, run loop

Once SSH works, a cross-compiled program goes from your editor to the target in one line:

```bash
$CC -O2 -o hello hello.c && scp hello root@192.168.7.2:/tmp/ && ssh root@192.168.7.2 /tmp/hello
```

`$CC` is set by sourcing the Yocto SDK environment script (see [SDKs and package management](../sdk-generation-package-management-licensing/)). For larger trees, `rsync -a build/ root@target:/opt/app/` copies only what changed, if rsync is installed on the target.

## Add a host alias

Typing the address and key every time gets old. Add an entry to `~/.ssh/config` on the host:

```text
Host qemu
    HostName 192.168.7.2
    User root
    IdentityFile ~/.ssh/target_ed25519
    StrictHostKeyChecking accept-new
```

Now `ssh qemu` and `scp hello qemu:/tmp/` work. `accept-new` trusts a host the first time you see it but still warns if its key changes later, which happens every time you rebuild and reflash an image with fresh host keys. Remove the old entry with `ssh-keygen -R 192.168.7.2` when that happens.
