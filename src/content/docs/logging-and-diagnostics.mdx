## Kernel messages

The kernel keeps a ring buffer of its own messages: driver probes, warnings, oopses. Read it with `dmesg`:

```bash
dmesg | tail -20
dmesg --level=err,warn      # util-linux dmesg; BusyBox dmesg lacks --level
dmesg | grep -i -E "error|fail|timeout"
```

The buffer has a fixed size (set by `CONFIG_LOG_BUF_SHIFT`), so on a busy system early boot messages can be overwritten. Save them early if you need them: `dmesg > /tmp/boot-dmesg.txt` from a start-up script.

Each message has a level from 0 (emergency) to 7 (debug). The console prints only messages more important than the console log level; change it at runtime with `dmesg -n 4`, or at boot with the `loglevel=` kernel argument.

## The systemd journal

On systemd images, `journald` collects kernel messages, service output and syslog calls in one place:

```bash
journalctl -b                 # this boot
journalctl -b -1              # previous boot (needs persistent storage)
journalctl -u status-web      # one service
journalctl -p warning -b      # warnings and worse, this boot
journalctl -f                 # follow, like tail -f
```

## Keeping logs across reboots

By default many embedded images keep the journal in RAM under `/run/log/journal`, so it vanishes at every reboot. Making it persistent costs flash writes. A balanced setting:

```ini
# /etc/systemd/journald.conf.d/10-persistent.conf
[Journal]
Storage=persistent
SystemMaxUse=16M
SyncIntervalSec=5min
```

:::caution[Flash wear]
Every sync writes to storage. On eMMC or raw NAND, aggressive logging can wear out the part years early. Cap the size, sync rarely, and log to RAM if the product does not need history.
:::

## BusyBox syslog

Without systemd, BusyBox provides `syslogd` (user-space messages) and `klogd` (forwards kernel messages to syslog). Logs go to `/var/log/messages` by default; `logread` reads them when syslogd runs with an in-memory buffer (`-C`).

```bash
logger -t myapp "calibration done"
logread | tail
```

## Ask the kernel directly

Many questions are answered without any logging at all:

| Question | Where to look |
|---|---|
| Memory left? | `/proc/meminfo` |
| What is using the CPU? | `top`, or `/proc/<pid>/stat` |
| Which drivers are bound? | `/sys/bus/*/drivers/` |
| Interrupt counts per CPU | `/proc/interrupts` |
| Mounted filesystems | `/proc/mounts` |
| Why did we last reboot? | Board-specific; often a watchdog or reset-cause register in `/sys` |
