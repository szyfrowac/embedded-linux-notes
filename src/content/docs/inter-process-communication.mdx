## Picking a mechanism

| Mechanism | Shape of data | Between | Notes |
|---|---|---|---|
| Pipe or FIFO | Byte stream, one direction | Related processes (pipe) or any (FIFO) | Simplest; good for a producer feeding one consumer |
| Unix domain socket | Stream or datagrams, both directions | Any processes | File permissions control access; can pass file descriptors |
| POSIX message queue | Discrete messages with priority | Any processes | Kernel keeps message boundaries; `mq_open`, `mq_send` |
| Shared memory | Raw memory | Any processes | Fastest, but you must add your own locking |
| D-Bus | Method calls and signals | Services on a system bus | Heavy, but standard on desktop-like stacks |

A sensor daemon that serves readings to several clients is a typical case for a Unix domain socket. A camera pipeline moving megabytes per frame is a case for shared memory.

## A Unix domain socket server

```c
/* sensord.c: answers every client with one reading, then closes. */
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <sys/stat.h>
#include <sys/un.h>

#define SOCK_PATH "/run/sensord.sock"

int main(void)
{
    int srv = socket(AF_UNIX, SOCK_STREAM, 0);
    struct sockaddr_un addr = { .sun_family = AF_UNIX };
    strncpy(addr.sun_path, SOCK_PATH, sizeof(addr.sun_path) - 1);

    unlink(SOCK_PATH);                       /* remove a stale socket file */
    if (bind(srv, (struct sockaddr *)&addr, sizeof(addr)) < 0) { perror("bind"); return 1; }
    chmod(SOCK_PATH, 0660);                  /* owner and group only */
    listen(srv, 4);

    for (;;) {
        int c = accept(srv, NULL, NULL);
        if (c < 0) continue;
        const char *msg = "temp_mC=41250\n";
        write(c, msg, strlen(msg));
        close(c);
    }
}
```

The client is the mirror image: `socket`, `connect` to the same path, `read`. For a quick test you do not need to write it; if `socat` is installed on the target:

```bash
./sensord &
socat - UNIX-CONNECT:/run/sensord.sock
```

:::note[Access control comes from the filesystem]
Because the socket is a file, ordinary permissions decide who may connect. Run the daemon as its own user and put clients in its group, instead of opening a TCP port that anything on the network could reach.
:::

## From processes to cores

On a heterogeneous chip, the same idea crosses CPU boundaries. In the [Chipwings module](../chipwings/06-phase4-rpmsg/), NuttX on one core and Linux on the others exchange messages over RPMsg. On the Linux side the channel appears as a character device (for example `/dev/rpmsg0` or `/dev/ttyRPMSG0`), so a Linux program talks to the real-time core with the same `read` and `write` calls you used above.
