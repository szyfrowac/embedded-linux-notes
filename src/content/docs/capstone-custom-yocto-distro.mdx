## Goal

Create `meta-acme-distro` containing a distribution called `acme`. Build an image with `DISTRO = "acme"` that differs from Poky in deliberate, documented ways.

## Layer layout

```text
meta-acme-distro/
├── conf/
│   ├── layer.conf
│   └── distro/
│       └── acme.conf
└── recipes-core/
    └── images/
        └── acme-image.bb
```

A starting point for the distro file:

```bitbake
# conf/distro/acme.conf
require conf/distro/poky.conf

DISTRO = "acme"
DISTRO_NAME = "Acme Embedded Linux"
DISTRO_VERSION = "1.0"

INIT_MANAGER = "systemd"
DISTRO_FEATURES:remove = "x11 wayland vulkan opengl bluetooth 3g nfc"
DISTRO_FEATURES:append = " seccomp"
```

`require conf/distro/poky.conf` keeps Poky's defaults so you only state the differences. Once you understand each setting, you can replace the `require` with your own complete configuration.

## Requirements

- The distro layer contains policy only: no machine configuration and no application recipes.
- Every difference from Poky is written down with the reason for it.
- `bitbake-layers show-layers` lists your layer, and `bitbake -e acme-image | grep ^DISTRO=` prints `acme`.
- The image boots in QEMU.

## Milestones

1. Create the layer with `bitbake-layers create-layer` and add it.
2. Add `acme.conf` based on Poky, switch `DISTRO`, rebuild, boot.
3. Change one policy at a time (init manager, removed features, a preferred version with `PREFERRED_VERSION_<recipe>`), rebuilding and booting after each.
4. Add `acme-image.bb` with the packages your product needs.
5. Compare `buildhistory` output between Poky and acme and summarise the differences.

## Acceptance checks

- A clean build directory plus your layers produces the same image again.
- Your write-up explains each change in one sentence.

:::tip[Stretch goal]
Set `DISTRO_VERSION` from a git tag, and add `/etc/os-release` fields so a running device reports exactly which build it is.
:::
