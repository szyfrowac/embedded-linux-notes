Use this page as a reference when a teammate asks "what did you change in X?". Every row links back to a lesson that explains it.

**Kinds**: **Bug** = upstream code was wrong (also on hardware). **Add** = a piece the design needs that did not exist. **Sim** = Renode only. **Test** = scripts that check the system.

**Board?** says whether the change matters on the Icicle Kit.

## A. Patches to upstream code

These are the changes most worth presenting: each one is a real defect or gap in a third-party project.

### NuttX 13.1 (`sw/patches/`, applied by `build-nuttx.sh`)

| Patch | File patched | Kind | What and why | Board? | Lesson |
|---|---|---|---|---|---|
| 0001 | `arch/risc-v/src/mpfs/mpfs_timerisr.c` | Bug | Pass the base `mtimecmp` address. `riscv_mtimer` already adds `8 * cpu_index`, so hart 1 programmed hart 2's timer and never got a tick. | Yes | 3 |
| 0002 | `arch/risc-v/src/mpfs/mpfs_ihc.c` | Add | Put the RPMsg resource table first in its struct and in section `.resource_table`, so the linker can pin it at `0xA2300000` where Linux looks. | Yes | 6 |
| 0003 | `mpfs_ihc.c` | Bug | Only treat a message as present when its MP bit is set (stale ack/message loop). Retry the notify with delay and log if it is lost. | Yes | 6 |
| 0004 | `mpfs_ihc.c` | Bug | Control register writes that do not mean to consume a message now write MP=1 (`MP_KEEP`). Fixes a read-modify-write race that ate messages. | Yes | 6 |
| 0005 | `mpfs_ihc.c` | Bug | Bound the notify retry budget to about 1 ms (was about a second per failed notification). A dead Linux no longer stalls the sender. | Yes | 8 |
